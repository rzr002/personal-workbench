# Promotion policy

Approve a private lesson only when it is specific, reusable, supported, compatible with current instructions, and safe to apply. Revise vague or overgeneralized lessons. Reject lessons derived from copied history, another person, a one-off workaround presented as a rule, or evidence that cannot be verified.

High-impact lessons require a concrete validation artifact before approval. These include destructive file operations, permission escalation, credentials, external messages, production changes, evaluation integrity, and any behavior that changes whose data may be learned from.

Promotion into the public plugin is a separate process: generalize the lesson, remove private context, add or update deterministic tests, run the privacy audit, inspect the Git diff, and version the plugin.
